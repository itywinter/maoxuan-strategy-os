# Stage Analysis

## Purpose

Determine the current development stage so the system solves today's problem rather than tomorrow's.

## Evidence, not labels

Years in business, headcount, founder ambition, or product sophistication do not by themselves define stage.

Possible dimensions:

- product: concept → prototype → validated solution → repeatable product → scalable platform
- market: exploration → first customer → reference building → repeatable acquisition → expansion
- commercial: opportunity discovery → paid validation → repeatable sales → predictable pipeline
- delivery: bespoke → standardized → repeatable → scalable
- customer adoption: awareness → pilot → budget → procurement → deployment → expansion

Dimensions may be at different stages.

## For the relevant stage define

- entry evidence
- stage objective
- must-do-now
- should-prepare
- can-wait
- should-stop
- exit criteria

## Warning signs

Premature scaling: hiring/expanding before validated demand and repeatability.

Endless validation: repeated pilots after enough evidence exists, avoiding commitment.

Stage can regress when customers, regulation, capability, or economics change.
